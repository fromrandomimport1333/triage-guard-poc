# Reproducing the experiments

Commands run from the extracted prototype directory, with dependencies installed
from `requirements-lock.txt`. Raw PhysioNet recordings and the dlib landmark
model are external inputs and are not distributed in this archive.

## Software checks

```text
python -m pytest tests -q
python run_cr01.py
python run_assurance_cases.py
python -m src.can_demo
python run_cusum_demo.py
python run_cusum_demo.py --enable-cusum
```

## Cardiac benchmark

Dataset: PhysioNet/CinC 2015 training set, DOI 10.13026/c9fg-a467.
`TRAINING_DIR` denotes the directory containing ALARMS, RECORDS, checksums and
all waveform/header pairs. `TRAINING_ZIP` denotes its original training archive.

```text
python run_cardiac_benchmark.py --training-dir "TRAINING_DIR" --archive "TRAINING_ZIP" --output-dir results/audit_reproduction
python run_cardiac_demo.py --record "TRAINING_DIR/a103l" --alarm Asystole
```

The benchmark audits input files, extracts pre-alarm features, selects models
using development folds, evaluates the fixed test split and writes metrics and
plots. It does not download recordings. Model choices and seeds are recorded in
`run_cardiac_benchmark.py` and `results/cardiac/config.json`.

The shipped baseline remains in `results/cardiac/`. Reproduction outputs in
`results/audit_reproduction/` can be compared by record ID, split, features,
model parameters, predictions and metrics. Wall-clock timings vary by machine.

`verify_reproduction.py` is a comparison utility for the specific output directory
`results/cardiac_clean/`; it also expects `results/clean_tests.xml`, generated by
`python -m pytest tests -q --junitxml=results/clean_tests.xml` in that environment.

## Diagnostics and integrated replay

```text
python scientific_audit.py --training-dir "TRAINING_DIR" --archive "TRAINING_ZIP"
python run_qa.py --training-dir "TRAINING_DIR"
```

The scientific audit recomputes metrics and diagnostic plots, replays saved
models, checks baseline preservation and retrieves official metadata over HTTPS.
`verify_provenance.py` provides a separate metadata check. `run_qa.py` executes
tests and synthetic/record-based demonstrations and writes current logs.
Diagnostic review of the existing test split is descriptive, not a new
independent clinical evaluation.

The camera script, synthetic-video comparison and external model requirements
are documented in `experimental/camera_frontend/README.md`.
